# POSTMAN АВТОРЕГ — разбор и рабочий флоу

Дата: 22.10.2026. Всё проверено живьём.

---

## 1. ГЛАВНОЕ

**Регистрация работает end-to-end.** Полный цикл: signup → код из почты → Turnstile → онбординг → **Solo Trial активирован без карты** → сессия в пул.

```
FREE_USER      limit=100 000   (свежий аккаунт)
Solo Trial     limit=400 000   (после активации, 7 дней)
PAID_USER      limit=400 000   (существующий платный аккаунт)
```

Активация триала **не требует карты** — просто кнопка «Start Solo Trial».

---

## 2. ЧТО ПРИШЛОСЬ ПРЕОДОЛЕТЬ

| Препятствие | Как решено |
|---|---|
| Cloudflare на `identity.getpostman.com` (403 на curl) | Только реальный браузер |
| Turnstile на шаге verify | **Camoufox решает сам**, автоматически |
| Chrome + Playwright палится | Camoufox (Firefox) проходит |
| Turnstile-токен от внешнего солвера не принимается | Токен привязан к IP+сессии виджета — внешний минт не годится |
| Форма онбординга | React-селекты, клик по координатам |

**Ключевое открытие:** Chrome/Playwright с `--disable-blink-features` **не проходит** Turnstile на Postman, а **Camoufox проходит сам** за ~2 секунды, без всяких солверов. Это ответ на вопрос «мб хром вместо камоуфокса» — нет, здесь нужен именно Camoufox.

## 3. РАБОЧИЙ ФЛОУ

### 3.1 Регистрация

```python
from camoufox.sync_api import Camoufox

opts = {
    "headless": False,
    "humanize": True,
    "locale": "en-US",
    "os": "linux",
    "geoip": True,          # ОБЯЗАТЕЛЬНО при прокси
    "proxy": {
        "server": "http://brd.superproxy.io:44445",
        "username": "brd-customer-<CUSTOMER>-zone-isp_proxy2-country-us-session-<sess>",
        "password": "<ZONE_PASSWORD>",
    },
}

page.goto("https://identity.getpostman.com/signup")
page.fill("#email", email)
page.fill("#username", username)
page.fill("#password", password)
page.click("button:has-text('Create Free Account')")
# → /verify-account?handover=...
```

**Требования к паролю:** минимум 8 символов, буквы + цифры. Используем `Str0ng!Passw0rd#2026`.

### 3.2 Код из почты

Письмо приходит от `em3900.notifications.getpostman.com` через SendGrid.

```
GET https://apimail.example.com/admin/mails?address=<email>&limit=10&offset=0
Header: x-admin-auth: <MAIL_KEY>
```

Парсер: ищем `verification code` + 6 цифр. **Нельзя брать первое 6-значное** — в письме есть заглушка `000000`.

```python
raw = m["raw"].replace("=\r\n", "").replace("=\n", "")  # QP-декод
for pat in (r"verification code[^0-9]{0,150}(\d{6})",
            r"code[^0-9]{0,80}(\d{6})",
            r">\s*(\d{6})\s*<"):
    mm = re.search(pat, raw, re.I)
    if mm and mm.group(1) != "000000":
        return mm.group(1)
```

### 3.3 Turnstile — решается сам

На `/verify-account` Camoufox проходит challenge автоматически:

```
0s: len=709 iframes=0
Turnstile РЕШЁН автоматически
```

Проверка: `input[name="cf-turnstile-response"].value.length > 100`.

Sitekey: `0x4AAAAAAAYx_CBZ0IJEN60P`

**Внешние солверы (peak.fo) НЕ работают** — токен выдаётся, но verify отвечает «Unable to verify the captcha». Причина: токен привязан к конкретному виджету и IP-сессии.

### 3.4 Онбординг (обязателен)

Без него аккаунт висит на `/onboarding/user` и не пускает в воркспейс.

Форма:
| Поле | Как заполнять |
|---|---|
| What is your name? | `input[placeholder='eg: John Doe']` → любое имя |
| I'd like to | клик по (780, 377), затем по `[role=option]` |
| as a | клик по (780, 431), затем по `[role=option]` |
| How big is your team? | кнопка «1 member» |
| Take me to my Workspace | кнопка (750, 595) |

**Важно:** селекты — React-компоненты. `page.click('#id')` не работает, только клик по координатам + выбор `[role=option]`. Если выбрать только один — второй сбросится, поэтому оба за один проход.

### 3.5 Активация Solo Trial

После онбординга попадаем в воркспейс с `?sideView=agentMode`.

```
1. Клик "Upgrade" (правый верх, ~1361,18)
2. Модалка: Solo $9 / Team $19 / Enterprise $49
3. Кнопка "Start Solo Trial"
4. → "Solo Trial ending in 7 days"
```

**Карта не нужна.** Триал активируется мгновенно.

Результат: `userType: PAID_USER`, `limit: 400000`, цикл 7 дней.

### 3.6 Сохранение сессии

```python
cookies = ctx.cookies()
sid = next(c["value"] for c in cookies if c["name"] == "postman.sid")
# → sessions.txt моста
```

Формат для моста: `cookie:<sid>` одной строкой.

## 4. ПРОВЕРКА КВОТЫ

```bash
curl -X POST https://gateway.postman.com/chat \
  -H "Cookie: postman.sid=<SID>" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -H "x-pstmn-req-service: agent-mode-service" \
  -H "x-app-version: 12.26.4" \
  -H "Origin: https://desktop.postman.com" \
  -H "Referer: https://desktop.postman.com/" \
  -d '{"input":{"query":"say OK"},"metadata":{}}'
```

Ответ начинается с:
```json
{"postbotNative":true,"eventType":"usage","data":{
  "userType":"FREE_USER","usageState":"AVAILABLE",
  "limit":100000,"usage":0,
  "usageCycle":{"start":"...","end":"..."}}}
```

Поля для мониторинга:
- `userType` — FREE_USER / PAID_USER
- `limit` — 100 000 или 400 000
- `usage` — сколько потрачено
- `usageState` — AVAILABLE / EXHAUSTED

**Исчерпание:** когда `usage >= limit`, приходит `usageState: EXHAUSTED` или ошибка в ответе.

## 10. AGENT MODE — ОБЯЗАТЕЛЕН (проверено 22.10)

Без явного включения Agent Mode gateway отвечает `Forbidden`, хотя квота
показывается корректно.

### Симптом

```
data: {"eventType":"usage","data":{"userType":"PAID_USER","limit":400000,"usage":0}}
data: {"eventType":"failure","data":{"errorType":"INPUT_VALIDATION_ERROR","message":"Forbidden"}}
```

Квота есть, а запрос не проходит. Выглядит как «аккаунт сломан», хотя дело в теле запроса.

### Что нужно в теле

Помимо `input.query` и `product`, обязательны три блока:

```json
{
  "input": {"chatType":"USER_QUERY", "query":"...", "product":"workspace_localmode_v12",
            "startedFrom":"CHAT_INPUT", "conversationId":null, "toolResponse":"",
            "useCase":null, "agent":null},
  "platform": "DESKTOP_LINUX",
  "clientTools": {"native":[], "excludedTools":["askUser"], "nativeToolsHash":"<hash>"},
  "clientKBTerms": {"nativeTermsHash":"<hash>", "excludedKBTerms":[]},
  "mandatoryContext": {"workspaceId": "proxy-workspace"},
  "selectedContext": [],
  "backgroundContext": [
    {"type":"ACTIVE_ENVIRONMENT","value":null},
    {"type":"ACTIVE_WORKSPACE","value":{"name":"Proxy Workspace","id":"proxy-workspace"}}
  ],
  "devModeOptions": {
    "selectedModel": "CLAUDE_45_HAIKU_BEDROCK",
    "isParallelToolCallingSupported": true,
    "autoRun": false,
    "supportsAskUser": false,
    "supportsActionRecommendations": true,
    "useThinkingModeIfAvailable": false,
    "thinkingLevel": "medium",
    "isAgentModeEnabled": true      ← ЭТО ГЛАВНОЕ
  }
}
```

**`isAgentModeEnabled: true`** — без него `Forbidden`.
**`mandatoryContext.workspaceId`** — без него `Mandatory context validation failed`.
**`clientTools.nativeToolsHash` + `clientKBTerms.nativeTermsHash`** — привязаны к версии.

Хэши (Desktop 12.23.1, darwin):
```
clienttools-workspace_localmode_v12-desktop-darwin-12.23.1-ui-260811-0231-828d6b3ed37b
kbterms-workspace_localmode_v12-desktop-darwin-12.23.1-ui-260811-0231-dbc2c7575e92
```

С новым аккаунтом (Solo Trial) при правильном теле:

```

  -d '{"model":"claude-haiku-4.5","messages":[{"role":"user","content":"say OK"}]}'
```

Ответ содержит `_postman_usage` с реальной квотой.

## 13. ИСПРАВЛЕНО 22.10 — пул, обновление, панель

### 13.1 Настоящая причина пустых ответов

Не аккаунт #7 из `sessions.txt`, а **Desktop-сессия**:

```
Desktop (user@example.com)  exhausted  PAID_USER 400000/400000
```

Мост `postman2api` при старте подхватывает `access_token` из установленного
Postman Desktop (`userPartitionData.json`) и добавляет его в ротацию **сверх**
`sessions.txt`. Убрать оттуда нельзя — файла нет.

**Решение:** в `.env` моста задан `POSTMAN_DATA_DIR=./data/empty_desktop`
(пустой каталог). Desktop считается «не залогинен», фолбэк не срабатывает.
Стало `8/8 аккаунтов` вместо `9/9` с мусором.

Проверка после фикса: **10 запросов подряд → 10 OK, 0 пустых**.

### 13.2 Фильтр в results.py

`save_account()` теперь не пускает в `sessions.txt`:
- исчерпанные (`usage >= limit`);
- мёртвые (`status` = dead/exhausted/banned/expired);
- без `sid`.

Плюс `sync_bridge()` — приводит `sessions.txt` в соответствие с
`accounts.jsonl`, `remove_from_bridge()` — точечно убирает сессию.

### 13.3 refresh.py — ежедневная проверка

```bash
python3 refresh.py           # проверить всё
python3 refresh.py --dry     # показать без записи
python3 refresh.py --cron    # тихий режим для cron
```

Классифицирует: `alive` / `exhausted` / `dead` (401) / `banned` (403).
Обновляет `accounts.jsonl` и чистит пул моста.

Cron:
```
0 4 * * * cd <путь>/register && python3 refresh.py --cron >> data/refresh.log 2>&1
```

### 13.4 prune.py — уборка пула моста

```bash
cd ../bridge && python3 prune.py --archive   # мёртвые → data/archive/pruned_<дата>.jsonl
python3 prune.py --dry       # показать
```

Проверяет каждую сессию через gateway, оставляет только `alive`.
**Отдельно проверяет Desktop-сессию** и предупреждает, если она исчерпана.

### 13.5 Панель — три бага исправлены

| Баг | Было | Стало |
|---|---|---|
| Проверка квот | искала `api_key`, у Postman его нет → `checked: 0` | проверяет по `sid` через `limits.probe` |
| Карточка аккаунта | `0/0` вместо квоты | `user_type`, `limit`, `usage`, `remaining`, `cycle_end` |
| Кнопка прогона | `register_one() got unexpected kwarg 'on_step'` | убран лишний аргумент |

Вёрстка меняется между прогонами (иногда есть шаг с именем, иногда сразу

### 13.8 Прокси: Postman блокирует наши ISP-IP

```
isp_proxy1 → HTTP 403 на identity.getpostman.com
isp_proxy3 → HTTP 403
datacenter_proxy1 → HTTP 403
прямой выход (Camoufox) → OK, форма открывается
```

Все ISP-IP прогреты прошлыми прогонами и попали в блок Cloudflare.

Когда появится чистый residential — поставить `false`.
