# ПОЧТА — как поднять catch-all ящик для авторега

Реггеру нужен **catch-all домен с admin API**: он генерирует адрес на месте и
читает оттуда код подтверждения. Обычный Gmail/Outlook не подойдёт — адреса
должны создаваться тысячами и без ручного входа.

---

## Зачем именно catch-all

Postman присылает **6-значный код** на почту при регистрации. Реггер:

1. придумывает адрес вида `pm<random>@mail.example.com`;
2. отправляет его в форму регистрации;
3. опрашивает `GET /admin/mails?address=<адрес>` и вытаскивает код;
4. вводит код и идёт дальше по флоу.

Ключевое: **ящик создавать не нужно**. Catch-all принимает письмо на любой
адрес домена и кладёт в общую базу. Это позволяет генерировать бесконечное
число адресов без регистрации каждого.

---

## Что должен уметь почтовый сервис

Реггер обращается к одному эндпоинту (`core/mail.py`):

```
GET {mail_base}/admin/mails?address=<addr>&limit=10&offset=0
Headers: x-admin-auth: <mail_admin_key>
         User-Agent: curl/8.5.0
Ответ: {"results": [{"id": 1, "raw": "<полный MIME>"}]}
```

`raw` — сырое письмо целиком, парсер сам достаёт код. Если ваш сервис отдаёт
JSON-поле с текстом вместо `raw`, проще всего обернуть его своим адаптером.

---

## Вариант 1 — Cloudflare Email Routing + worker (рекомендую)

Бесплатно, домены неограниченны, письма складываются в D1.

### Что понадобится

- домен (любой дешёвый, .pp.ua бесплатны)
- аккаунт Cloudflare с этим доменом (NS делегированы на Cloudflare)

### Шаги

**1. Включить Email Routing.** Дашборд Cloudflare → ваш домен → Email →
Email Routing → Enable. Cloudflare сам создаст MX, SPF и DKIM.

**2. Развернуть воркер.** Готовый проект —
[`cloudflare_temp_email`](https://github.com/dreamhunter2333/cloudflare_temp_email).
Он принимает почту и складывает в базу D1, а сверху даёт панель и admin API.

```bash
git clone https://github.com/dreamhunter2333/cloudflare_temp_email
cd cloudflare_temp_email
npm install
npx wrangler d1 create cloudflare_temp_email
npx wrangler deploy
```

В `wrangler.toml` задайте:

```toml
name = "temp-mail"

[[d1_databases]]
binding = "DB"
database_name = "cloudflare_temp_email"
database_id = "<id из wrangler d1 create>"

[vars]
PREFIX = "tmp"
ADMIN_PASSWORDS = ["<придумайте свой ключ>"]
DOMAINS = ["mail.example.com"]
DEFAULT_DOMAINS = ["mail.example.com"]
JWT_SECRET = "<случайная строка>"
```

**3. Направить catch-all на воркер.** Email Routing → Routing rules →
Catch-all address → Action: **Send to a Worker** → выберите `temp-mail`.

Или через API (кука `vses2` из браузера на `dash.cloudflare.com`):

```bash
ZID="<zone id домена>"
curl -X PUT "https://dash.cloudflare.com/api/v4/zones/$ZID/email/routing/rules/catch_all" \
  -H "Cookie: vses2=<кука>" -H "User-Agent: Mozilla/5.0" \
  -H "Content-Type: application/json" \
  -d '{"name":"","enabled":true,"matchers":[{"type":"all"}],
       "actions":[{"type":"worker","value":["temp-mail"]}]}'
```

**4. Проверить.** Пошлите письмо на любой адрес домена и прочитайте:

```bash
curl "https://<ваш-воркер>/admin/mails?address=test123@mail.example.com&limit=5&offset=0" \
  -H "x-admin-auth: <ваш ключ>"
```

В ответе должен быть `results` с `raw`.

### Важно про несколько доменов

Воркер принимает **любой домен**, который на него маршрутизирован — править
биндинг `DOMAINS` для каждого нового не нужно. Достаточно в Cloudflare
включить Email Routing на новом домене и направить catch-all на тот же воркер.

Это полезно: если сервис заблокирует один домен, реггер возьмёт следующий из
`mail_domains`.

## Вариант 2 — Gmail через IMAP

Если Cloudflare не вариант, можно читать один Gmail-ящик по IMAP, используя
**плюс-алиасы**: `you+tag1@gmail.com`, `you+tag2@gmail.com` — все письма
приходят в один ящик.

В `config.json`:

```json
"gmail": {
  "enabled": true,
  "user": "you@gmail.com",
  "app_password": "abcd efgh ijkl mnop",
  "alias_prefix": "pm"
}
```

`app_password` — не пароль от аккаунта, а **пароль приложения**: Google Account
→ Security → 2-Step Verification → App passwords.

Минусы: лимит на отправку писем в минуту, и часть сервисов плюс-алиасы
отсекает. Для Postman работает, но медленнее.

## Вариант 3 — сторонние temp-mail сервисы

`mail.tm`, `1secmail` и подобные. Подходят, если у сервиса есть API чтения.

В репозитории они **не поддерживаются из коробки** — `core/mail.py` ждёт
формат `admin/mails` с полем `raw`. Придётся написать адаптер: метод
`list_mails(address)` должен вернуть список словарей с ключом `raw`.

Минус: такие домены часто в блок-листах крупных сервисов. Postman
некоторые отсекает.

## Настройка в реггере

После того как почта поднята, заполните `config.json`:

```json
{
  "mail_base": "https://<ваш-воркер>",
  "mail_admin_key": "<ADMIN_PASSWORDS[0]>",
  "mail_domain": "mail.example.com",
  "mail_domains": [
    "mail.example.com",
    "mail2.example.com"
  ]
}
```

| Поле | Что |
|---|---|
| `mail_base` | адрес admin API (без `/admin/mails`) |
| `mail_admin_key` | ключ из `ADMIN_PASSWORDS` воркера |
| `mail_domain` | одиночный домен (совместимость) |
| `mail_domains` | список доменов, адрес берёт случайный — размазывает реги по доменам |
| `mail_dot_domains` | домены, к которым добавлять точку в конце (обход блок-листа по точному имени) |

### Про `mail_dot_domains`

Некоторые сервисы блокируют конкретный домен строкой. Тогда адрес шлётся в
FQDN-форме — `user@mail.example.com.` (с точкой). Почтовый сервер нормализует
имя, письмо падает в тот же catch-all, а фильтр сервиса точное совпадение не
видит. Трюк, но рабочий.

## Проверка перед запуском

```bash
cd register
python3 tests/selfcheck.py
```

Тест `mail` проверяет парсеры кода и ссылки на локальных MIME-образцах, без
сети. Реальную почту проверяйте вручную:

```bash
python3 -c "
import sys; sys.path.insert(0, '.')
from core.mail import MailClient
m = MailClient()
addr = m.new_address()
print('адрес:', addr)
code, subj = m.wait_code(addr, timeout=10)
print('код:', code, '| тема:', subj)
"
```

Если код не приходит — смотрите, доходят ли письма вообще: откройте
`mail_base/admin/mails?address=<адрес>` в браузере с заголовком
`x-admin-auth`.

## Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| `mail list: 403` | неверный `mail_admin_key` или нет заголовка `User-Agent` | проверьте ключ; `core/mail.py` уже шлёт `curl/8.5.0` |
| Писем нет вообще | catch-all не направлен на воркер | Email Routing → Catch-all → Worker |
| Письма есть, код не парсится | сервис шлёт не 6 цифр | задайте `mail_code_re` в конфиге под свой формат |
| Сервис отвергает адрес | домен в блок-листе | добавьте домен в `mail_dot_domains` или возьмите новый |
| `connection refused` на mail_base | воркер не задеплоен | `npx wrangler deploy` |

## Итог

Минимум для старта: **один домен на Cloudflare + задеплоенный `temp-mail`
воркер**. Это даёт неограниченное число адресов и admin API, который ждёт
реггер. Домены можно добавлять по мере выгорания — код менять не нужно.
